## 1. 项目结构：一张图讲清楚"代码在哪、为什么这么放"

```
src/
├─ main.js            入口：createApp → use(Pinia) → use(Router) → 插件 → 指令 → mount
├─ App.vue            根组件：导航栏 + <RouterView> + Transition + KeepAlive
├─ router/index.js    路由表（懒加载、动态参数、别名、重定向、404、守卫）
├─ data/              数据层：terms.js（24 节气）、quiz.js（题库）—— 和 Vue 无关的纯 JS
├─ composables/       可复用逻辑：useCountdown / useLocalStorage / useSeasonNow
│                     / useTermFilter / useToast
├─ stores/            Pinia：theme / favorites / ui
├─ directives/        自定义指令：reveal / highlight
├─ plugins/           插件：siteInfo（$site 全局属性 + provide）
├─ components/        33 个组件，分 4 类：
│   ├─ layout/(3)     导航、页脚、主题切换
│   ├─ common/(11)    与业务无关的基础组件：卡片 / 按钮 / 弹窗 / 标签页 / 评分 …
│   ├─ terms/(7)      节气业务组件：卡片 / 网格 / 筛选条 / 时间轴 / 圆盘 / 详情面板
│   ├─ home/(4)       首页专用：主视觉 / 倒计时 / 功能入口 / 收藏条
│   └─ workshop/(8)   知识演示：食材推荐 / 知识小测 / 诗词轮播 / 异步组件 / 渲染函数 …
└─ views/(6)          6 个页面：Home / Terms / TermDetail / Workshop / About / NotFound
```

**重点回答"为什么这样分层"**：
- `common` 里的组件**完全不知道"节气"是什么**，只认 props 和插槽，所以能到处复用；
- 页面负责"取数据、传数据"，组件负责"怎么显示"；
- 所有能算出来的东西（筛选结果、数量统计、下一节气）都用 `computed` 派生，**绝不手动维护第二份数据**。

## 2. 数据是怎么流动的（被问到就画这条线）

```
data/terms.js（静态数据 + 纯函数 getNextTerm/getCurrentTerm）
        │
        ├── composables/useSeasonNow.js  ──→  HomeView  ──→  HeroSection / CountdownCard / TermWheel
        │        （当前节气、下一节气、剩余天数）              （props 往下传）
        │
        ├── composables/useTermFilter.js ──→  TermsView  ──→  TermFilterBar（v-model 双向）
        │        （搜索/筛选/排序/统计，全是 computed）        TermGrid → TermCard（props + emit）
        │
        └── stores/favorites.js（Pinia）  ──→  首页 / 图鉴 / 详情 三处共享同一份收藏
                 （localStorage 持久化）
```

一句话：**单向数据流 + 状态集中在少数几个地方**。想改数据，只有两个入口——组合式函数里的 `ref`，或者 Pinia 的 action。

## 4. 必讲的 8 个知识点（每个都按"原理 → 代码 → 演示 → 追问"准备）

### ① 响应式与 computed：全站没有一处"手动更新列表"

- **原理**：`ref` 声明状态；`computed` 会自动收集依赖并缓存，依赖变了才重算。
- **代码**：`composables/useTermFilter.js`
  ```js
  const filtered = computed(() => {
    const kw = keyword.value.trim().toLowerCase()
    return (unref(source) || [])
      .filter((t) => (season.value === 'all' || t.season === season.value))
      .filter((t) => !kw || [t.name, t.pinyin, t.tagline, ...t.foods].join(' ').toLowerCase().includes(kw))
      .sort(SORTERS[sortBy.value])
  })
  ```
- **演示**：图鉴页输入"饺子"→ 结果立刻变；清空 → 恢复。代码里搜索"filtered"只有这一处定义。
- **追问**：*"为什么不用 watch 手动更新一个 list 数组？"*
  → 因为那是"派生状态"，手动同步会出现数据和 UI 不一致（忘了同步、顺序错乱）。computed 由 Vue 保证一致，还带缓存。

### ② 组件通信：props / emits / v-model / 插槽，四件套都用在哪儿

- **props 向下**：`TermCard :term="term" :favorite="…"`
- **emits 向上**：`TermCard` 点星星 → `emit('toggle-favorite', term)` → `TermsView` 调 store
- **组件 v-model**：`StarRating`、`SearchInput`、`BaseModal`、`BaseTabs` 都是 `defineModel()`
  ```js
  // StarRating.vue —— 一行等于 "prop + emit update:modelValue"
  const model = defineModel({ type: Number, default: 0 })
  ```
- **插槽**：
  - 默认插槽：`BaseCard` 的 `<slot />`
  - 具名插槽：`BaseCard` 的 `#header` / `#footer`
  - 作用域插槽：`EmptyState` 把 `suggestion` 交给父组件
  - **动态插槽名**（这个最容易被追问）：
    ```html
    <!-- BaseTabs.vue：插槽名由当前选中的 tab 决定 -->
    <slot :name="active">{{ activeTab?.emptyText || '暂无内容' }}</slot>
    ```
    父组件写 `<template #hou>`、`<template #customs>` 就填进去了。
- **追问**：*"父组件怎么改子组件的数据？"* → 不直接改，用 v-model 或 emit，保持单向数据流。

### ③ 组合式函数：把"每秒刷新"封装成一行

- **代码**：`composables/useCountdown.js`
  ```js
  export function useCountdown(target) {
    const now = ref(Date.now())
    const remainingMs = computed(() => Math.max(0, targetDate.value.getTime() - now.value))
    function start() { stop(); timer = setInterval(() => (now.value = Date.now()), 1000) }
    onMounted(start)      // 组合式函数里也能用生命周期钩子
    onUnmounted(stop)     // 谁申请谁释放
    return { days, hours, minutes, seconds, isOver, start, stop }
  }
  ```
- **组件里**：`const { days, hours, isOver } = useCountdown(() => props.nextDate)` —— 就这一行。
- **演示**：首页倒计时点"暂停计时 / 继续计时"。
- **追问**：*"和 mixin 有什么区别？"* → 来源清晰（显式 import + 返回值命名），不会命名冲突，类型和逻辑都看得见。

### ④ Pinia：为什么收藏必须放 store

- **代码**：`stores/favorites.js`（Setup Store：`ref`=state、`computed`=getter、函数=action）
- **关键坑**：`const { list } = useFavoritesStore()` 会**丢失响应性**，必须 `storeToRefs`。
- **演示**：图鉴页收藏 → 首页"我的收藏"立刻出现 → 刷新页面还在（localStorage）。
- **扩展开关**：`stores/theme.js`（浅色/深色/跟随系统 → 写 `<html data-theme>`，CSS 变量接管配色）。

### ⑤ Vue Router：六个考点一次说完

`router/index.js`：

1. **懒加载**：`component: () => import('@/views/TermsView.vue')` → 每个页面一个独立 chunk（构建日志可证）
2. **动态参数**：`/terms/:id` + `props: true` → 组件直接 `defineProps({ id })`，不依赖 `useRoute()`
3. **别名与重定向**：`alias: ['/about-us']`、`/list → /terms`
4. **404 通配符**：`/:pathMatch(.*)*`
5. **全局守卫**：`beforeEach` 统一改 `document.title`
6. **滚动行为**：`scrollBehavior`（后退恢复位置、锚点平滑滚动）

- **追问**：*"history 模式刷新 404 怎么办？"* → 服务器要回退到 index.html：Netlify 用 `_redirects`，GitHub Pages 在构建时把 `index.html` 复制成 `404.html`。

### ⑥ KeepAlive + Transition + Teleport：三个内置组件

- **KeepAlive**：`App.vue` 里 `<KeepAlive :include="['TermsView']">` → 图鉴页筛选完 → 进详情 → 返回，**筛选条件还在**。
  - 坑：被缓存的组件不再触发 `onMounted`，读 URL 参数要用 `onActivated`。
- **Transition / TransitionGroup**：页面切换、卡片增删、Toast 进出。类名规律 `v-enter-from → v-enter-active → v-enter-to`。
- **Teleport**：`BaseModal` / `ToastHost` / `BackToTop` 都 `to="body"`，避免被父元素的 `overflow` / `transform` 影响层级。

### ⑦ 异步组件 + Suspense + 渲染函数 + 自定义指令（"进阶四件套"）

- **异步组件**：`workshop/AsyncFactCard.vue`
  ```js
  const AsyncFactContent = defineAsyncComponent({
    loader: () => import('./AsyncFactContent.vue'),  // 独立 chunk，用到才下载
    loadingComponent: LoadingBox, errorComponent: ErrorBox, delay: 200
  })
  ```
  内容组件里写了 **顶层 await**（模拟请求接口），外层用 `<Suspense>` 显示 fallback。点"再抽一条"改 `key` → 组件重建 → 重新走一遍加载。
- **渲染函数**：`workshop/RenderFunctionDemo.vue` 用 `h()` 手写了一个"节气排行榜"组件，和模板写法对照。
- **自定义指令**：`directives/reveal.js`（IntersectionObserver 滚动浮现）、`highlight.js`（参数 `:whole`、修饰符 `.ignore-case`）。
- **追问**：*"三者为啥放一起讲？"* → 都是"`<template>` 之外控制渲染的方式"：异步组件控制"什么时候加载"，渲染函数控制"怎么生成 VNode"，指令控制"DOM 层面的行为"。

### ⑧ 工程化：能部署才叫做完

- **别名**：`vite.config.js` 里 `@ → src`
- **部署路径**：`base: process.env.BASE_PATH || '/'`，GitHub Pages 是子路径 `/shiling-zhi/`，Netlify 是根路径
- **CI**：`.github/workflows/deploy.yml`：装 pnpm → 装 Node → `pnpm install` → `pnpm build`（注入 `BASE_PATH`）→ 复制 `index.html` 为 `404.html` → 发布到 Pages
- **验证**：`pnpm build` 看 chunk 拆分；用 Edge 无头模式 `--dump-dom` 抓渲染后的 DOM 检查内容与错误关键字

## 6. 老师可能追问的问题 & 参考答案

| 问题 | 参考答案 |
| --- | --- |
| 为什么用 Vue 不用 React？ | 课程要求 + Vue 的 SFC 把模板、逻辑、样式放一个文件里，小项目上手快；组合式 API 的逻辑复用方式（组合式函数）比 HOC/render props 直观。 |
| `ref` 和 `reactive` 的区别？ | `ref` 能包任意类型，模板里自动解包，`.value` 访问；`reactive` 只能包对象、解构会丢响应性。本项目统一用 `ref`，一致性更好。 |
| `computed` 和 `watch` 什么时候用哪个？ | 要"算出一个值"用 `computed`；要"做副作用"（写 localStorage、打日志、重启定时器）用 `watch`。本项目 `useLocalStorage` 就是 `watch` 写存储。 |
| 为什么收藏不放组件里？ | 首页、图鉴、详情三处都要读，放组件里就得层层传 props（prop drilling），放 Pinia 一次解决。 |
| 组件怎么知道自己是第几个？ | 用 props 传（`FeatureList` 的 `v-for (item, index)`），或者用作用域插槽把 `index` 交给父组件。 |
| `v-if` 和 `v-show` 的区别？ | `v-if` 真正销毁/创建（有创建开销，适合不常切）；`v-show` 只切 `display`（适合频繁切）。本项目弹窗用 `v-if`+Transition（要过渡），Tab 面板用动态组件切换。 |
| `:key` 有什么用？ | 帮助 Vue 复用/识别节点。列表增删动画、`<component :is>` 重建（异步组件"再抽一条"）都靠它。 |
| 数据从哪来？有接口吗？ | 目前是本地静态数据 `data/terms.js`，纯函数计算日期；没后端。下一步可以接公开节气 API。 |
| 页面刷新白屏吗？ | 不白屏，但首屏是客户端渲染。生产构建已经把 JS 按页面拆包，首屏只加载首页和公共代码。 |
| 有没有做移动端适配？ | `main.css` 里是流式布局 + 媒体查询；导航在 720px 以下变汉堡菜单；圆盘用 `ResizeObserver` 动态算半径。 |
| 怎么保证代码没写错？ | `pnpm build` 构建通过 + Edge 无头模式抓 6 条路由的 DOM 扫描 `TypeError / Vue warn`，全部干净；另外用截图人工核对过每个页面。 |
| 最大的难点是什么？ | 圆盘那次——CSS 动画的 `transform` 覆盖了行内样式的 `transform`，24 个点全叠到圆心且**不报错**，只能靠截图发现；后来改用 `left/top` 定位才解决。 |
| 如果要做全栈呢？ | 加后端接口 → `useFetch` 组合式函数封装请求 → `Suspense` 显示加载态；用户体系用 token + 路由守卫；收藏从 localStorage 迁到数据库。 |
